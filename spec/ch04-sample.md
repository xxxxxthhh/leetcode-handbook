# 第 04 章 · 栈与单调栈（样章）

## §1 一句话心智模型

**单调栈：每个元素都在找"左边或右边第一个比我大（或小）的人"；栈里存的，是那些还没等到答案的人。**

新元素进场时，把栈里所有"等到答案了"的人依次弹出并结账——弹出的那一刻就是它的答案揭晓的那一刻。每个元素最多进出栈一次，所以整体 O(n)，这就是它把 O(n²) 暴力扫描打下来的全部秘密。

普通栈是它的退化形态：不比大小、只配对嵌套结构（括号、路径、表达式），本章热身用它找感觉。

## §2 识别信号

| 题面出现… | 想到 |
|---|---|
| "下一个更大 / 更小元素" | 单调栈（模板 A） |
| "第一个比它高 / 低 / 便宜的…" | 单调栈（模板 A） |
| "柱状图 / 矩形 / 最大面积" | 单调栈（模板 A + 哨兵） |
| "滑动窗口的最大 / 最小值" | 单调队列（模板 B） |
| 括号匹配、嵌套、"撤销上一步" | 普通栈 |
| 你写出的暴力解，内层循环在"向左/右扫，找第一个满足条件就停" | 单调栈优化信号 |

**分流条件**（决策树用）："连续子数组 + 最值" 且窗口大小固定 → 单调队列；窗口不固定、条件是"和/种类数" → 滑动窗口（第 03 章）；"子数组和恰好为 K" → 前缀和 + 哈希（第 13 章）。

## §3 模板代码

### 模板 A · 下一个更大元素（覆盖本章 80% 的题）

```python
def next_greater(nums):
    n = len(nums)
    ans = [-1] * n                # 【插槽】默认值:没等到答案的人得什么
    stack = []                     # 【骨架】存下标;栈内对应值单调递减
    for i, x in enumerate(nums):   # 【骨架】
        while stack and nums[stack[-1]] < x:   # 【插槽】比较方向:< 找更大,> 找更小;是否带 = 见翻车点②
            j = stack.pop()        # 【骨架】j 此刻等到了答案
            ans[j] = x             # 【插槽】答案形式:值 x / 距离 i-j / 下标 i
        stack.append(i)            # 【骨架】
    return ans
```

默写口诀：**存下标、递减栈、弹出即结账**。

### 模板 B · 单调队列（仅 239 一题需要，认脸级）

```python
from collections import deque

def max_sliding_window(nums, k):
    q, ans = deque(), []           # q 存下标,对应值单调递减,队首=当前窗口最大
    for i, x in enumerate(nums):
        while q and nums[q[-1]] <= x:   # 新人把比自己弱的全部挤出去
            q.pop()
        q.append(i)
        if q[0] <= i - k:               # 队首已滑出窗口
            q.popleft()
        if i >= k - 1:
            ans.append(nums[q[0]])
    return ans
```

与模板 A 的唯一区别：窗口会从左边过期，所以要用双端队列在队首淘汰出窗的人。

## §4 题目分层

**热身（普通栈建直觉）**
- [20 Valid Parentheses](https://leetcode.com/problems/valid-parentheses/) — 纯配对：左括号进栈，右括号找栈顶结账。体会"栈顶 = 最近一个未完成的事"。
- [155 Min Stack](https://leetcode.com/problems/min-stack/) — 辅助栈同步记录"当前最小"。插槽思维预演：栈里存什么由问题决定。

**标准（模板 A 直接套）**
- [739 Daily Temperatures](https://leetcode.com/problems/daily-temperatures/) — 模板 A 原题。唯一插槽改动：`ans[j] = i - j`（答案要距离，这就是为什么骨架存下标）。
- [496 Next Greater Element I](https://leetcode.com/problems/next-greater-element-i/) — 模板 A + 哈希把答案映射回子数组。
- [503 Next Greater Element II](https://leetcode.com/problems/next-greater-element-ii/) — 循环数组变形：遍历 `2n` 次、下标取 `i % n`，其余不变。

**变体（模板要扭的地方）**
- [853 Car Fleet](https://leetcode.com/problems/car-fleet/) — 先按位置排序算到达时间，再用栈合并车队。识别难度大于实现难度：它的"第一个追上我的人"结构藏在排序之后。
- [84 Largest Rectangle in Histogram](https://leetcode.com/problems/largest-rectangle-in-histogram/) ⭐ — 模板 A 换方向（递增栈、找两侧第一个更矮的），末尾补哨兵 0 强制清算。见翻车点⑤，本章唯一必须掌握的 hard。
- [239 Sliding Window Maximum](https://leetcode.com/problems/sliding-window-maximum/) ⭐ — 模板 B 原题，认脸即可。

## §5 常见翻车点 + 自测

**翻车点**
1. **存值还是存下标**：默认存下标。答案涉及距离或位置（739）时值救不了你；存下标永远能取回值，反之不行。
2. **严格与非严格（`<` vs `<=`）**：有重复元素时决定相等的人算不算"答案"。84 题里用 `>=` 弹出可以简化等高柱的处理；写题前先问一句"两个相等的元素，谁给谁结账"。
3. **方向记反**：找"更大"用递减栈，找"更小"用递增栈。记法：栈里留着的都是"还没等到更大的人"，所以他们自然从底到顶递减。
4. **循环数组忘了取模**：503 走两遍时下标必须 `i % n`，第二遍只结账、不再入栈也可以（微优化，非必须）。
5. **清算时机**：遍历结束后栈里剩下的人是"永远没等到答案的人"。要么接受默认值（739 的 0），要么补哨兵强制结账（84 的末尾 0）——忘掉这一步是 84 题 WA 的头号原因。

**自测 · 30 秒识别模式**（答案倒排在页脚，正式版为交互组件）

- Q1 [901 Online Stock Span]：返回今天之前连续多少天股价 ≤ 今天。你的第一反应是哪个模式？
- Q2 [402 Remove K Digits]：删掉 k 个数字使剩下的数最小。哪个模式？
- Q3：给定数组和整数 k，求"和恰好等于 k 的连续子数组"个数。哪个模式？

> 答案：Q1 单调栈（"之前第一个比我高的"的镜像问法）；Q2 单调栈（维持递增序列，大的先删）；Q3 **前缀和 + 哈希，不是本章**——"恰好为 K"是分流关键词，见 §2 分流条件。每章自测都会混入一道非本章题，防止"读哪章选哪章"。
